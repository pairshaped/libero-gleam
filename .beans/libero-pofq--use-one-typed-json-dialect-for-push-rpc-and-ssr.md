Make push, RPC, and SSR share the same typed JSON value representation.

Problem:
- These paths must not each grow their own representation for user values. JSON becomes maintainable only if the generated graph has one contract.

Acceptance criteria:
- Push payloads, RPC request and response bodies, and SSR payloads call the same generated JSON encode and decode helpers for user values.
- Representative fixtures for all three paths have matching typed value shapes for the same user type.
- Contract hash and version checks run before accepting a payload generated from a different graph.
- Tests fail if one path emits a special-case shape for the same type.
